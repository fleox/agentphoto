## Invariants and traps

- **stdout is the protocol.** Anything on stdout besides the one JSON object (or the MCP frames) breaks agents. Logs go through `io.err` / `process.stderr`; `bin.ts` reroutes `console.log/info/debug`; engine progress (model downloads) is forwarded to stderr by the session. `agent/cli.test.ts` checks the envelope and exit codes.
- **Hints differ per door.** The CLI rewrites tool names in every `hint` (`withCliHints`, `printError`); MCP and `/api/tools/call` keep tool names; `tools call` prints raw (`{ raw: true }`). A new tool whose name appears in op hints needs a `TOOL_COMMANDS` entry, or CLI users get a tool name (`agent/output.test.ts`). `check` and `export` are left alone on purpose (plain words).
- **Errors need a hint.** Exit-2 `CliError`s without one get the command usage; anything unknown becomes `internal`. A new `OpsError` code needs an `OPS_HINTS` entry and an exit code in `knownError` (`validation` / `invalid` → 2).
- **Pixel tools are always listed on Node.** `nodeHost` always has an `engine` (the session starts Chrome lazily on the first call), so `tools list`, MCP and `/api/tools` show `render_preview`, `export`, `image_analyze`, `remove_background`, `mask_generate`; a missing Chrome or engine build fails at call time with `no-browser` / `engine-missing` + hint. `src/ai/tools.test.ts` pins `TOOL_ORDER`, the `READ_ONLY` and `ENGINE` lists — keep them equal to the CLAUDE.md tool list. MCP attaches `previewImages` (render_preview files) as `image` blocks; `isRefusal` (`status: "refused"` or `applied: false` with errors) → `isError: true`.
- **Read-only MCP depends on `mutating`.** A wrong flag exposes a write tool under `mcp --read-only` (`agent/mcp/server.test.ts` "read-only mode"). Destructive / idempotent / open-world hints are the sets in `server.ts`.
- **One engine session per project folder, per process.** `engineSession(dir)` keeps one Chrome + one local server (`/__engine/` = `dist/engine`, `/__library/`, `/project/`, `/__models/`) + one page running `window.agentphoto`. Calls are `Runtime.evaluate` with JSON-embedded arguments; images come back as `{ base64 }` and `decodeImage` keeps every other field (`bbox`, `errors`, …). Before each call `sync()` compares size + mtime of the document's referenced files and calls `window.agentphoto.invalidate([...])` for changed ones (a regenerated mask under the same name). A dead page / browser is restarted once (`engine-crashed` after that). Page-side method names are the `EngineMethod` union: change `src/engine/headless.ts`, `session.ts` and `sessionEngineHost` together.
- **Timeouts.** `AGENTPHOTO_CDP_TIMEOUT_MS` (default 180 000) caps engine calls; AI calls (`backgroundMask`, `segmentMask`) get at least 15 minutes because the first use downloads the model; the engine page must be ready in 30 s; browser startup has its own 20 s timeout in `launchBrowser`. CI sets `AGENTPHOTO_CDP_TIMEOUT_MS=180000`. `AGENTPHOTO_DEBUG=1` echoes the page console on stderr.
- **Node 22.** `engines` says ≥ 22 and `vite.agent.config.ts` targets `node22`: `cdp.ts` needs the global `WebSocket`; `doctor` fails its `node` check below 22.
- **The CLI bundle never contains the AI runtime.** `vite.agent.config.ts` (`noEngineDeps`) fails the build if `@huggingface/transformers`, `onnxruntime-*` or `src/engine/ai.ts` is pulled in: import engine *types* only from `agent/`. Commands lazy-load their modules so `help` / `version` start instantly.
- **Model cache proxy** (`modelsRoute`, mounted by the session and the Studio server): `/__models/<repo>/resolve/<rev>/<file>` is served from `modelsDir()` or downloaded once from `https://huggingface.co/`, streamed to the page while written to a `.part` file renamed when complete; concurrent requests share one download; upstream 404s pass through uncached (transformers.js probes optional files). Path segments are checked against traversal (`parseModelPath`). Tests inject `fetchImpl` (`agent/render/models.test.ts`) — never the network.
- **Temp dirs.** Chrome profiles (`agentphoto-chrome-*`) are removed on close and on process exit, and a launch sweeps stale ones. Tests create temp folders only through `tempDir(prefix)` from `agent/testing/tmp.ts`.
- **E2E tests skip silently** without Chrome or `dist/engine` (`agent/e2e.test.ts`: `describe.skipIf(!CAN_RUN)`). A green `npm test` before a build proves nothing about rendering: build first, as CI does. Tests never download AI models.
- **Local server security.** `startLocalServer` binds 127.0.0.1; `resolveUnder` never serves outside a mount (`agent/render/server.test.ts`); the Studio API answers 403 to a foreign Host / Origin (`agent/commands/serve.test.ts` "refuses paths outside the project and foreign hosts / origins"). Keep `localGuard` first in every route list.
- **Shared `dist/`.** `npm run build` rewrites `dist/`, which other agents' e2e tests, `check:skills` and `build-cli-docs.mjs` read. When several agents work at once, only one builds (or each builds into its own folder and sets `AGENTPHOTO_DIST`; `.agentphoto-tmp/` is git-ignored and excluded from Vitest for such scratch work). `check-skills.mjs` and `build-cli-docs.mjs` always read the shared `dist/agent/agentphoto.mjs`.

## How to add a command, action or option

1. Implement it in `agent/commands/<area>.ts` calling `src/ops/` or `callTool` (no business rule here); options from `util.ts`, destructive or overwriting writes through `confirmOrPlan` + `YES_OPTION`, output via `printResult`.
2. Declare `usage`, `summary`, `options`, `subcommands` (`writes`, `destructive`); a new command goes into `COMMANDS` in `index.ts`. Subcommand usages must start with the command name (`cli.test.ts`).
3. Test with `cli([...])` / `ok([...])` from `agent/testing/cli.ts` in `agent/cli.test.ts` (or a test next to the command).
4. Regenerate `docs/cli.md`: `npm run build:agent && node scripts/build-cli-docs.mjs` (`scripts/cli-docs.test.ts` fails when stale).
5. Update every skill / reference in `plugin/skills/` that mentions it (`check:skills` rejects unknown options), then `npm run hermes:build`. A Hermes helper reading a changed output field is a contract (AGENTS.md "Hermes is generated").

## How to add or change an AI tool's exposure

1. Handler and schema: `src/ai/docTools.ts` or `src/ai/imageTools.ts` (see `engine-internals`), name in `TOOL_ORDER`, `READ_ONLY` / `ENGINE` in `src/ai/tools.test.ts`, the CLAUDE.md tool list.
2. Host needs (pixels, files): extend `EngineHost` / `ToolHost` in `src/ai/types.ts` additively (contract — report it), implement it in `sessionEngineHost` (`agent/render/session.ts`) + `src/engine/headless.ts`, and in the Studio's `pageEngineHost` (`src/studio/backend/pageEngine.ts`) so both doors match.
3. MCP annotations: add the name to `DESTRUCTIVE` / `IDEMPOTENT` / `OPEN_WORLD` in `agent/mcp/server.ts` when relevant; CLI hint mapping in `TOOL_COMMANDS`; a CLI command that wraps it.
4. Document it in [docs/mcp.md](../../../docs/mcp.md), `MCP_INSTRUCTIONS` if it changes the workflow, and the skill that uses it.

## Skills, Hermes, generated docs

- `plugin/skills/` is the source: `agentphoto-retouch` (core), `agentphoto-cutout`, `agentphoto-design`, `agentphoto-publish`. Frontmatter: `name` (= folder), `description` (what + when, < 1024 chars), `license: PolyForm-Noncommercial-1.0.0`, `compatibility`, `metadata.version` (= package.json), `allowed-tools`.
- Every command in a skill is `npx -y @fleox/agentphoto@<version> <command> … --json` on **one line**, run for real, in order, on a scratch project outside the repo (inside it, npx resolves the local package). Use `my-photo` as the project name so a skill's commands replay as a sequence.
- `check-skills.mjs` (after `npm run build`) runs the built CLI's `help --json` and `doc validate` on full document blocks (`"version"` + `"layers"`, errors **or warnings** fail), checks versions (`plugin/.claude-plugin/plugin.json`; `.claude-plugin/marketplace.json` must have no `version` and `source: "./plugin"`; `dist/version.json`), portable frontmatter, English, relative links, valid ```json blocks, pins in README / docs, and a `changelog.json` entry for the version.
- Hermes: never edit `hermes/skills/`. New Python helper → `HELPERS` + `TAGS` in `build-hermes.mjs`, docstring first line, `hermes/README.md`, `hermes/tests/test_scripts.py` (stdlib only, `fake_engine.py` driven through `AGENTPHOTO_CMD`). `npm run check:hermes` needs `python3`.
- Generated docs: the reference part of `docs/cli.md` (`npm run docs:cli`, `npm run check:docs`), `docs/catalog.md` (`UPDATE_DOCS=1 npx vitest run src/ops/docs.test.ts`). `docs/studio-api.md` is hand-written but owned here: a new Studio API route updates it in the same change.
- Studio API route: `startStudioServer` in `serve.ts` + `docs/studio-api.md` + `agent/commands/serve.test.ts`, a method on the Studio `Backend` in both `remote.ts` and `local.ts` (tell the Studio owner — `studio-internals`). After a write, `watcher.ignoreWritten([...])` so the Studio does not reimport its own change.

## Releases and CI

1. `changelog.json` entry (newest first: `version`, `date`, `breaking`, `changes[]`, `actions[]`); `agentphoto.minSkillsVersion` in package.json if older skills break with this CLI. Tree clean.
2. `npm version patch|minor|major` runs the `version` script: `sync-version.mjs` (plugin.json, skills' `metadata.version`, every pinned `@fleox/agentphoto@x.y.z` in skills, README, AGENTS.md, `hermes/README.md` and `docs/`), `npm run build`, `build-hermes.mjs`, `build-cli-docs.mjs`, then `git add -A plugin hermes .claude-plugin README.md AGENTS.md docs` (all of it lands in the version commit). [docs/releasing.md](../../../docs/releasing.md) lists the same steps.
3. Push on `main`: `git push && git push --tags`. `release.yml`: tag = package.json version, `npm ci`, typecheck, build, tests (`AGENTPHOTO_CDP_TIMEOUT_MS=180000`), `check:skills`, `check:hermes`, CLI docs check, packed-tarball smoke test (`new demo --template social-quote`, `check`), `npm install -g npm@latest` (trusted publishing needs npm ≥ 11.5.1), `npm publish --provenance --access public --ignore-scripts` via OIDC (no token), skipped when the version is already on the registry, then `gh release create` from the `changelog.json` entry (skipped if it exists).
4. Trusted publisher on npmjs.com: user `fleox`, repository `agentphoto`, workflow `release.yml`, no environment. It must be saved **before** the run, or the publish fails. The very first version (0.1.0) was published by hand (npm only allows trusted publishing on an existing package). Re-run a failed release with `gh run rerun <id>` (idempotent).
5. Verify from outside the repo: `cd /tmp && npx -y @fleox/agentphoto@<v> version --json`. `gh` is installed and authenticated here: `gh run list --workflow release.yml`, `gh run view <id> --log-failed`.
- `ci.yml` (push to `main`, PRs) also runs `node scripts/build-library.mjs --check`, a CLI smoke test (`version`, `help`, `templates list`) and `npm pack --dry-run`. No Claude attribution in commits, PRs or releases.

## QA with parallel AI agents

- One background agent per area, each in its own worktree (`isolation: "worktree"`, `.claude/worktrees/` is git-ignored), with its own `dist/` (`AGENTPHOTO_DIST`) and its own `studio --port`.
- **Blind QA**: the agent gets only `plugin/skills/` plus `help` / `catalog` output, never `src/`. It must render, LOOK at every image (`render` prints the paths; `--compare` and `--zoom` for details), `check`, export, and judge the result harshly against the brief. Photos from `library/images` or CC0 files only; AI models are downloaded once into the shared cache (`AGENTPHOTO_MODELS` to isolate it).
- Test the published package from a folder outside the repo with the pinned `npx -y @fleox/agentphoto@<version>`; projects under `/tmp/qa-<agent>/`.
- Verify each reported bug in the code before fixing; fix in `src/ops/` / `agent/` / skills with tests; give fix agents disjoint files and "no version bump, no shared `npm run build`, no push". Merge into one integration branch, run the checks below, then fast-forward `main` after the user's go.
